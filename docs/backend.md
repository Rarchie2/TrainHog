# TrainHog backend (Supabase)

The app talks to one Supabase project (London region). Without one configured
it runs on demo data, so nothing breaks before setup.

## Pieces

| Piece | Where |
| --- | --- |
| Tables and security rules | `supabase/migrations/0001_trainhog.sql` |
| Starter library (25 exercises, 10 sessions, Hogan's business) | `supabase/migrations/0002_starter_library.sql`, generated by `node --experimental-strip-types scripts/starter-sql.mjs` |
| Session parts, exercise categories (Jamie's structure) | `supabase/migrations/0003_session_structure.sql` |
| Per-business branding (colours, logo) and video credits | `supabase/migrations/0004_branding.sql` |
| Connection | `src/config.ts` (project URL and publishable key) and `src/data/backend.ts` |
| Loading and saving | `src/data/remote.ts`, used by `src/data/store.tsx` |
| Sign-in screens | `src/components/SignIn.tsx` |

## How people get in

- No passwords. People type their email and get a sign-in link (`signInWithOtp` with `emailRedirectTo: trainhog://auth`). Tapping it on the phone opens the app, which finishes sign-in from the link (`signInFromLink` in `src/data/backend.ts`). If the email template ever includes `{{ .Token }}`, the 6-digit code box works too (`verifyOtp`).
- Right after sign-in the app calls `claim_account()`. That links the login to:
  - a **trainer** if the email is in `trainer_invites`, or
  - a **client** if a trainer has added a client with that email.
- Anyone else sees "Ask Hogan to add you".
- "Try the demo" on the sign-in screen opens the sample data (useful for App Review).

## Security in one paragraph

Row-level security is on for every table. Trainers can read and write everything in their business. Clients can read only their own plan, history, messages and replies, plus the session library. They can add only their own sessions, check-ins, pain reports, diary notes, weigh-ins and community posts. Trainer notes live in `client_private`, which clients can't read. The community feed reads first names through the `community_members` view. A trigger stops clients changing their email, business or invite status.

## Setup checklist (once)

1. Create a project called TrainHog in the London region.
2. Run the migration files, in order.
3. Add the trainers: `insert into trainer_invites (email, business_id) values ('<email>', '7a1e5b0d-0000-4000-a000-000000000001');`
4. Authentication > URL Configuration > Redirect URLs: add `trainhog://**` (the phone app) and `https://rarchie2.github.io/TrainHog/**` (the web app). Without these, the email link goes to the Site URL instead of the app.
5. Put the project URL and publishable key in `src/config.ts`.
6. Before more than a handful of clients: set up a custom SMTP sender (e.g. Resend with a verified domain). Supabase's built-in email sends only about 2 emails an hour, and its templates can't be edited. With custom SMTP, the Magic Link template can also show `{{ .Token }}` as a code.

- `sessions.programme` and `sessions.phase` hold phased templates.
